## View-by-View Interaction Contract

### View 1 — List View (`view === 'list'`)

**Title:** "World Sets"

**Layout (top to bottom):**
1. `.dialog-section-label` — "World Sets"
2. `.map-list` — one `.map-list-item` per world set name; clicking selects AND immediately calls `setActiveWorldSet(name)` then transitions to nodes view (D-04)
3. `.dialog-row` — create input: `<input type="text">` (160px wide) + `.btn-primary` "Create"
4. `.dialog-error` (conditional) — shown below create row on error
5. `.dialog-buttons` — `<button>` "Close" (plain, no class)

**Delete action:** `.btn-danger` "Delete" inline in each `.map-list-item` (right side, `justify-content: space-between`). Does NOT require typing the name — a single click shows an inline confirm prompt (see Copywriting Contract). Claude's discretion: confirm is an inline `.dialog-warn` block with "Yes, delete" and "Cancel" buttons.

**Empty state:** If no world sets exist, replace `.map-list` with `<p style={{ color: '#888', margin: '8px 0' }}>No world sets found.</p>` (mirrors OpenMapDialog line 112 pattern).

---

### View 2 — Node Management View (`view === 'nodes'`)

**Title:** "World Set: {activeWorldSetName}"

**Layout (top to bottom):**
1. `.dialog-section-label` — "Maps in this world set"
2. `.map-list` — one `.map-list-item` per node, showing `mapName` + scale label; `.btn-danger` "Remove" on right
3. `.dialog-buttons` — left-aligned `.btn-secondary` "Back"; right-aligned `.btn-primary` "Add map node"

**Empty state:** If world set has no nodes, replace `.map-list` with `<p style={{ color: '#888', margin: '8px 0' }}>No maps added yet.</p>`

**Remove action:** Clicking "Remove" on a node calls `removeNode(mapName)` (BFS cascade) then `saveWorldSet()`. No separate confirmation — the action is immediately undoable by re-adding the node (consistent with warn-not-block philosophy; nodes view is not destructive of files).

---

### View 3 — Configure-Node View (`view === 'configure'`)

**Title:** "Add Map Node"

**Layout (top to bottom, each as `.dialog-row`):**
1. **Map** — `<select>` (220px) listing all maps from `listMaps()`; label "Map"
2. **Scale row (conditional)** — shown only when `!selectedMapData?.feetPerUnit`; label "Scale"; `<select>` (220px) from `MAP_SCALES`; expansion row disappears when user selects a map that already has `feetPerUnit`
3. **Parent** — `<select>` (220px) showing "None (root)" + all maps currently in the world set; label "Parent"
4. **Anchor Col** — `<input type="number">` (80px); shown only when parent is not "None"; label "Anchor col"
5. **Anchor Row** — `<input type="number">` (80px); shown only when parent is not "None"; label "Anchor row"
6. **Z** — `<input type="number">` (80px); label "Z level"
7. **Z label** — `<input type="text">` (160px); label "Z label"; optional
8. `.dialog-warn` (conditional) — shown for scale inversion or footprint overlap warnings; does NOT block "Add"
9. `.dialog-error` (conditional) — shown for duplicate mapName or cycle; BLOCKS "Add" button (`.btn-primary` disabled)
10. `.dialog-buttons` — left `.btn-secondary` "Back"; right `.btn-primary` "Add" (disabled while loading or hard error)

**Validation timing:** On submit attempt only (not real-time). Claude's discretion confirmed: validate when user clicks "Add", not on each field change. Exception: the scale expansion row appears/disappears in real-time as the map picker changes.

Source: CONTEXT.md D-01, D-02, D-03; RESEARCH.md Pattern 6, Pattern 7.

## State Transitions

```
list view
  → click world set item → setActiveWorldSet(name) → setView('nodes')
  → click "Create" (after entering name) → create + setActiveWorldSet → setView('nodes')
  → click "Close" → onClose()

nodes view
  → click "Back" → setView('list')
  → click "Add map node" → reset configure form state → setView('configure')
  → click "Remove" on node → removeNode() → saveWorldSet() → stay in nodes view

configure view
  → click "Back" → clear error/warnings → setView('nodes')
  → click "Add" (success, no warnings) → D-03 sequence → saveWorldSet() → setView('nodes')
  → click "Add" (success, with warnings) → D-03 sequence → saveWorldSet() → show warnings → setView('nodes')
  → click "Add" (hard error) → show .dialog-error → stay in configure view
```

On entering configure view: reset `error`, `warnings`, `selectedMap`, `selectedMapData`, `parentMapName`, `anchorCol`, `anchorRow`, `z`, `zLabel`, `needsScale`.

Source: CONTEXT.md D-01 navigation; RESEARCH.md Pitfall 6.

## Accessibility

- All interactive elements are `<button>` or native `<input>`/`<select>` — keyboard navigable by default
- Disabled state: `.btn-primary:disabled` (opacity 0.4, `cursor: not-allowed`) — apply via `disabled` attribute on loading or hard error
- Touch targets: buttons use `min-height: 36px` (`.btn-primary`, `.btn-secondary`); acceptable for tablet (iPad)
- Click-to-dismiss: `.dialog-backdrop onClick={onClose}` + `.dialog onClick={(e) => e.stopPropagation()}` — required pattern on all dialog views
- No ARIA roles needed beyond native semantics for this phase
