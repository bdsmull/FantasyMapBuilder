## View-by-View Interaction Contract

### Panel State: No Active World Set (PANEL-05)

When `activeWorldSetName === null`:
- `WorldHierarchyPanel` renders `null` — the component is not mounted, not just hidden
- `LayerPanel` receives `flex: 1` (fills the full left panel height)
- No resize handle is rendered

### Panel State: World Set Active (PANEL-01)

When `activeWorldSetName !== null`:
- Left panel stacks: `WorldHierarchyPanel` (top, flexible height) → `.panel-resize-handle` (4px) → `LayerPanel` (bottom, flexible height)
- Default split: hierarchy panel gets 60% of left panel height, layer panel gets 40%
- Minimum hierarchy panel height: 80px; minimum layer panel height: 60px
- Drag state is stored in component state (`useState<number>` for hierarchy panel pixel height); not persisted to localStorage
- Panel heights recalculate on window resize (via ResizeObserver or window resize event listener)

### Hierarchy Panel Header (D-02)

- `.hierarchy-header` shows "WORLD SET" as `.panel-header` uppercase label on the left
- Right side: if `worldSetNames.length > 1`, render `.hierarchy-switcher` as `<select>` — changing it calls `setActiveWorldSet(value)`; if exactly one world set, render the name as a `<span className="hierarchy-switcher">` (static, no dropdown)
- World set names come from a `listWorldSets()` call; store on first render and update when dialog changes the list
- Header does NOT have a "Close" or deactivate action — world sets are deactivated only via the management dialog

### Tree Rendering (D-03)

Render recursively starting from `rootNodes()`, then `childrenOf(mapName)` for each node:

```
root nodes (depth=0)
  ├─ child (depth=1)
  │   └─ grandchild (depth=2)
  └─ child (depth=1)
```

- Each node row is `.hierarchy-node` with `padding-left: calc(12px + depth * 16px)`
- Toggle: `.hierarchy-toggle` — shows `▾` (expanded) or `▶` (collapsed); leaf nodes render toggle with `visibility: hidden` (not `display: none`) to preserve column alignment
- All nodes start expanded (D-03)
- Collapse state: `Record<string, Set<string>>` keyed by world set name; inner set contains collapsed mapNames; survives map navigation within session; resets on page reload
- When a node is collapsed, its children are not rendered (not just hidden)
- Map name: `.layer-name` span (ellipsis overflow, flex: 1)
- Active map: `.hierarchy-node.active` on the node whose `mapName === currentMapName`
- Warning badge: `.hierarchy-badge` `⚠` rendered after `.layer-name` when node has any validation issue; hovered via `onMouseEnter`/`onMouseLeave` to show/hide `.hierarchy-tooltip`

### Warning Badge Tooltip (D-05)

Tooltip content lists each applicable issue as a separate line (newline-separated within the `⚠` tooltip):
- "Missing map: '{mapName}' file not found"
- "Missing scale: no feetPerUnit set on this map"
- "Scale inversion: this map is the same size or larger than its parent"
- "Footprint overlap: conflicts with '{otherMap}' at the same Z level"

One `⚠` per node regardless of issue count. Tooltip shows all issues for that node.

Validation check runs at render time using the same helpers as `detectOverlaps` from Phase 1 + map data from store.

### Click to Navigate (PANEL-02, D-06)

Clicking any `.hierarchy-node` row (not the toggle arrow, not the badge):
1. If `isDirty === false`: call `navigateToMap(mapName, { saveFirst: false })` directly
2. If `isDirty === true`: show dirty-guard dialog (see Dirty-Guard Dialog below)

Clicking the toggle arrow (`.hierarchy-toggle`) only toggles collapse state — does NOT trigger navigation.

### Dirty-Guard Dialog (D-06)

Rendered as a `.dialog-backdrop` → `.dialog` modal when navigation is attempted on a dirty map:

**Layout (top to bottom):**
1. `.dialog-title` — "Unsaved Changes"
2. `<p>` body copy — "You have unsaved changes in the current map. What would you like to do?"
3. `.dialog-buttons` — three buttons left to right:
   - `.btn-secondary` "Keep Editing" → dismiss dialog, stay on current map
   - `.btn-danger` "Discard Changes" → `navigateToMap(targetName, { saveFirst: false })`
   - `.btn-primary` "Save Map" → `navigateToMap(targetName, { saveFirst: true })`

Dialog dismisses when "Keep Editing" is clicked or Escape key is pressed. Clicking backdrop (`onClick` on `.dialog-backdrop`) dismisses (Keep Editing behavior — no navigation).

### Context Menu (D-07, PANEL-04)

Right-clicking a `.hierarchy-node` row:
1. Prevent default browser context menu (`e.preventDefault()`)
2. Store `contextMenuTarget = { mapName, x: e.clientX, y: e.clientY }` in component state
3. Render `.hierarchy-ctx-menu` at `style={{ top: y, left: x }}` with `position: fixed`
4. Dismiss by: clicking outside (global `mousedown` listener while menu is open), pressing Escape (global `keydown` listener)

Menu items (in order):
1. "Add child here" — calls handler that opens `WorldSetDialog` in configure view with `initialParentMapName` pre-set to the right-clicked node's `mapName`
2. "Change parent" — opens `WorldSetDialog` in configure view with the right-clicked node's current data pre-loaded for editing; Claude's discretion on exact prop shape
3. "Remove from world set" — class `danger`; calls `removeNode(mapName)` then `saveWorldSet()`; no confirmation prompt (consistent with Phase 4 nodes-view Remove and the warn-not-block pattern)

Clicking a context menu item closes the menu after executing the action.

## State Transitions

```
No world set active
  → setActiveWorldSet(name) [from management dialog] → panel mounts, tree renders

World set active, map not dirty
  → click tree node → navigateToMap(name, { saveFirst: false }) → map loads, active highlight moves

World set active, map dirty
  → click tree node → dirty-guard dialog appears
  → "Keep Editing" → dialog closes, no navigation
  → "Discard Changes" → navigateToMap(name, { saveFirst: false }) → map loads
  → "Save Map" → navigateToMap(name, { saveFirst: true }) → map saves, then loads

Tree node with children
  → click ▾ → node collapses (children unmounted), toggle becomes ▶
  → click ▶ → node expands (children rendered), toggle becomes ▾

Right-click tree node → context menu appears at cursor
  → "Add child here" → WorldSetDialog opens (configure view, parent pre-filled) → context menu closes
  → "Change parent" → WorldSetDialog opens (configure view, node pre-loaded) → context menu closes
  → "Remove from world set" → removeNode() + saveWorldSet() → node disappears from tree → context menu closes
  → click outside or Escape → context menu closes

Resize handle
  → pointerdown → drag mode starts, pointermove on document adjusts split height, pointerup ends drag
```

## Accessibility

- Tree nodes are `<li>` elements within a `<ul>` — semantic list structure; screen readers announce as list
- Toggle button is a `<button>` element (not a `<span>`) — keyboard activatable with Enter/Space
- Warning badge `⚠` has `title` attribute containing the full tooltip text as fallback for screen readers (tooltip is also shown visually on hover)
- Dirty-guard dialog: focus moves to "Keep Editing" button on open; Escape key dismisses
- Context menu: rendered as `<ul role="menu">` with `<li role="menuitem">` children; Escape key closes
- Touch targets: tree node rows have `min-height: 28px` from `.hierarchy-node` padding (acceptable for desktop; iPad users use left panel which is hidden on narrow screens per existing media query)
- Pointer events on resize handle: use `setPointerCapture` on `pointerdown` to track drag across the full document
